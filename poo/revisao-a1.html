1. Classes, objetos e instâncias

A classe define um molde; o objeto é uma instância concreta criada a partir dela.

Classe Produto→ cria →produto1produto2

Declarando a classe

public class Produto
{
    public string Nome { get; set; }
    public decimal Preco { get; set; }

    public void Exibir()
    {
        Console.WriteLine($"{Nome}: {Preco:C}");
    }
}

Instanciando no Program.cs

Produto produto = new Produto();

produto.Nome = "Teclado";
produto.Preco = 149.90m;

produto.Exibir();

new Produto() cria um objeto em memória.

Ponto-chaveDuas instâncias da mesma classe possuem as mesmas propriedades disponíveis, mas podem guardar valores diferentes.

2. Propriedades e modificadores de acesso

Propriedades representam características. Modificadores definem onde um membro pode ser acessado.

ModificadorAcessoUso comum
publicQualquer classe.Métodos e propriedades que farão parte do uso externo.
privateSomente a própria classe.Dados internos protegidos.
protectedClasse e classes filhas.Regras que subclasses podem reutilizar.
internalMesmo projeto/assembly.Uso interno da aplicação.

Encapsulando uma regra

private decimal _preco;

public decimal Preco
{
    get { return _preco; }
    set
    {
        if (value >= 0)
            _preco = value;
    }
}
EncapsulamentoO objeto protege seus dados e controla como eles podem ser alterados.

4. Console, leitura e conversão

Console.ReadLine() lê texto. Quando deseja um número, o texto precisa ser convertido.

Saída

string nome = "Ana";
double nota = 8.5;

Console.WriteLine("Resultado");
Console.WriteLine($"Aluno: {nome}");
Console.WriteLine($"Nota: {nota:F1}");

Entrada com Parse

Console.Write("Digite sua idade: ");
int idade = int.Parse(Console.ReadLine());

Console.WriteLine($"Idade: {idade}");

Funciona somente se a entrada puder ser convertida.

int.Parse x int.TryParse

FormaResultadoEntrada inválida
int.Parse(texto)Retorna um inteiro.Gera erro/exceção.
int.TryParse(texto, out valor)Retorna true ou false e preenche o valor.Permite tratar sem encerrar o programa.
Console.Write("Digite a idade: ");

if (int.TryParse(Console.ReadLine(), out int idade))
{
    Console.WriteLine($"Idade cadastrada: {idade}");
}
else
{
    Console.WriteLine("Idade inválida.");
}

6. Métodos e seus retornos

Métodos são comportamentos. O tipo antes do nome informa o que o método devolve.

AssinaturaUso
public void ExibirDados()Executa uma ação, mas não retorna valor.
public double CalcularMedia()Calcula e retorna um número decimal.
public bool EstaAprovado()Retorna verdadeiro ou falso.
public void AtualizarNota(double nota)Recebe um parâmetro para executar uma ação.
public class Aluno
{
    public string Nome { get; set; }
    public double Nota1 { get; set; }
    public double Nota2 { get; set; }

    public double CalcularMedia()
    {
        return (Nota1 + Nota2) / 2;
    }

    public bool EstaAprovado()
    {
        return CalcularMedia() >= 7;
    }

    public void ExibirResultado()
    {
        if (EstaAprovado())
            Console.WriteLine($"{Nome} foi aprovado.");
        else
            Console.WriteLine($"{Nome} não foi aprovado.");
    }
}
Regra práticaQuando outro trecho do programa precisa usar o resultado, retorne o valor. Não limite o método a apenas imprimir na tela.

7. Herança

Herança cria uma especialização: a classe filha reutiliza características e comportamentos da classe base.

Pessoa→ classe base de →AlunoProfessor
public class Pessoa
{
    public string Nome { get; set; }

    public void Apresentar()
    {
        Console.WriteLine($"Meu nome é {Nome}.");
    }
}

public class Aluno : Pessoa
{
    public string Matricula { get; set; }

    public void Estudar()
    {
        Console.WriteLine($"{Nome} está estudando.");
    }
}
Correto

Relação “é um”

Aluno é uma Pessoa. Cachorro é um Animal.

Incorreto

Relação “tem um”

Aluno tem um Endereço; portanto, Aluno : Endereco não faz sentido.

8. Polimorfismo

Objetos de classes filhas podem ser tratados como o tipo base e executar comportamentos diferentes.

public class Animal
{
    public string Nome { get; set; }

    public virtual void EmitirSom()
    {
        Console.WriteLine("Som do animal");
    }
}

public class Cachorro : Animal
{
    public override void EmitirSom()
    {
        Console.WriteLine($"{Nome}: au au!");
    }
}

public class Gato : Animal
{
    public override void EmitirSom()
    {
        Console.WriteLine($"{Nome}: miau!");
    }
}
List<Animal> animais = new List<Animal>();
animais.Add(new Cachorro { Nome = "Bolt" });
animais.Add(new Gato { Nome = "Luna" });

foreach (Animal animal in animais)
{
    animal.EmitirSom();
}
ResultadoA lista é de Animal, mas cada instância executa sua própria implementação: cachorro late e gato mia.
Palavras-chavevirtual indica que a base permite sobrescrita opcional; override define a nova implementação na classe filha.

9. Classes e métodos abstratos

Uma classe abstrata representa uma ideia geral incompleta. Ela serve como base, mas não pode ser criada diretamente.

public abstract class Funcionario
{
    public string Nome { get; set; }

    public abstract decimal CalcularSalario();

    public void ExibirNome()
    {
        Console.WriteLine($"Funcionário: {Nome}");
    }
}

public class Horista : Funcionario
{
    public decimal ValorHora { get; set; }
    public int Horas { get; set; }

    public override decimal CalcularSalario()
    {
        return ValorHora * Horas;
    }
}
Classe abstrata
  • Pode ter propriedades.
  • Pode ter métodos prontos.
  • Pode conter métodos abstratos.
  • Não pode ser instanciada.
Método abstrato
  • Não possui corpo na classe base.
  • Obriga a classe concreta a implementá-lo.
  • A implementação utiliza override.
Não compilaFuncionario f = new Funcionario(); é inválido, pois a classe é abstrata.

10. Interfaces

Uma interface define um contrato: classes que a implementam devem fornecer os comportamentos exigidos.

public interface INotificavel
{
    void EnviarMensagem(string mensagem);
}

public class Email : INotificavel
{
    public string Destinatario { get; set; }

    public void EnviarMensagem(string mensagem)
    {
        Console.WriteLine($"Email para {Destinatario}: {mensagem}");
    }
}

public class Sms : INotificavel
{
    public string Telefone { get; set; }

    public void EnviarMensagem(string mensagem)
    {
        Console.WriteLine($"SMS para {Telefone}: {mensagem}");
    }
}
List<INotificavel> canais = new List<INotificavel>();
canais.Add(new Email { Destinatario = "aluno@email.com" });
canais.Add(new Sms { Telefone = "11999999999" });

foreach (INotificavel canal in canais)
{
    canal.EnviarMensagem("Prova disponível.");
}

Classe abstrata x interface

Classe abstrataInterface
Compartilha uma base comum, inclusive propriedades e implementação.Define comportamentos que diferentes classes devem cumprir.
Uma classe só pode herdar de uma classe base.Uma classe pode implementar várias interfaces.
Ex.: Funcionario com Nome e salário.Ex.: INotificavel para e-mail e SMS.

11. Exemplo integrador: pagamentos

Este exemplo reúne interface, classe abstrata, método abstrato, herança, polimorfismo, condição, entrada validada e repetição.

public interface IExibivel
{
    void ExibirResumo();
}

public abstract class Pagamento : IExibivel
{
    public string Descricao { get; set; }
    public decimal Valor { get; set; }

    public abstract decimal CalcularValorFinal();

    public void ExibirResumo()
    {
        Console.WriteLine($"{Descricao}: {CalcularValorFinal():C}");
    }
}

public class Pix : Pagamento
{
    public override decimal CalcularValorFinal()
    {
        return Valor * 0.95m;
    }
}

public class Cartao : Pagamento
{
    public int Parcelas { get; set; }

    public override decimal CalcularValorFinal()
    {
        if (Parcelas > 1)
            return Valor * 1.05m;

        return Valor;
    }
}

// Program.cs
Console.Write("Digite o valor: ");
if (!decimal.TryParse(Console.ReadLine(), out decimal valor))
{
    Console.WriteLine("Valor inválido.");
    return;
}

List<Pagamento> opcoes = new List<Pagamento>();
opcoes.Add(new Pix { Descricao = "Pix", Valor = valor });
opcoes.Add(new Cartao { Descricao = "Cartão", Valor = valor, Parcelas = 3 });

foreach (Pagamento pagamento in opcoes)
{
    pagamento.ExibirResumo();
}
Abstração

Pagamento centraliza dados comuns.

Polimorfismo

Pix e cartão calculam resultados diferentes.

Validação

TryParse protege a entrada.

12. Pontos de atenção e erros comuns

Objeto

Declarar sem instanciar

Produto p; apenas declara. Use new Produto() antes de acessar propriedades.

Conversão

Confiar em Parse

Texto inválido gera erro. Para entrada do usuário, use TryParse.

Método

Retorno incoerente

Um método que calcula a média deve retornar o valor quando ele será reutilizado.

Herança

Usar “tem um” como herança

Um carro tem motor, mas não é um motor. Modele corretamente.

Override

Esquecer a base

Para sobrescrever, o método base precisa ser virtual ou abstract.

Interface

Contrato incompleto

Uma classe que implementa uma interface precisa fornecer todos os membros exigidos.

Regra de ouroVerifique tipos das propriedades, assinatura dos métodos, palavras-chave de sobrescrita e se a classe realmente representa a relação proposta pelo enunciado.

14. Questões de revisão rápida

Tente responder antes de revelar.

1. Qual tipo usar para idade, preço e CPF?

int para idade, preferencialmente decimal para preço e string para CPF.

2. Qual a diferença entre int.Parse e int.TryParse?

Parse lança erro com texto inválido; TryParse retorna false e permite tratar a situação.

3. Quando um método deve retornar void?

Quando apenas executa uma ação e nenhum resultado precisa ser devolvido para uso posterior.

4. Por que Aluno : Pessoa faz sentido, mas Aluno : Endereco não?

Aluno é uma pessoa, mas apenas possui um endereço. Herança modela a relação “é um”.

5. Para que servem virtual e override?

virtual permite sobrescrever o comportamento da base; override implementa o comportamento específico na classe filha.

6. É possível fazer new de uma classe abstrata?

Não. Deve-se instanciar uma classe concreta derivada que implemente os métodos abstratos.

7. Quando uma interface é útil?

Quando diferentes classes precisam cumprir o mesmo contrato, como Email e Sms implementando INotificavel.
